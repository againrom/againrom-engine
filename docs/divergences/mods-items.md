## Divergences

Implementation and researched ROM1 behaviour differ, or the owner ruled against a claim.

| ID | Subsystem | Owner directive | ROM1 behaviour (claims) | Implemented behaviour | Type | Reason | Revisit condition | Status |
|---|---|---|---|---|---|---|---|---|
| DIV-4005 | mods / a material a mod allows on a row | Owner (BACKLOG T9): a mod allows or forbids a material for one tier of an armour, shield or weapon row; an allowed pair the install has no picture of needs the picture from the mod | `DAT-MATMASK-020`, `ITEM-PICT-050`: a row holds five 16-bit material masks, one per tier, and the shipped masks predict the picture set exactly (416 legal items). `ITEM-224`: the shop walk and random selection test the mask; direct construction and LOAD do not. `ITEM-225`: a missing inventory picture takes the error path, with no alternate picture | `data/items.toml` `[[material]]` sets or clears one bit of a row's mask after the merge; the shop candidates, the stock draw and the item picture lookup read the merged mask. An allowed pair the install has no inventory picture of takes the mod's PNG; without one the mod is refused when it loads, naming the file, line, row, tier and material. The doll paints the figure layers the install holds for the pair's code and none where it holds none. The pair keeps its own 16-bit code in the SAV, and the mod mark names the mod set | DEVIATION | The original's data holds no pair its masks lack and no picture for one; the mod supplies the picture | An owner decision to let a mod supply figure layers for a pair | ACCEPTED |
| DIV-4006 | mods / a weapon row a mod adds | Owner (BACKLOG T9): a mod adds a weapon row as a copy of a shipped row it names and changes only parameters whose meaning a pinned claim states | `DAT-WEAPCELLS-023`: the weapon table holds 28 entries, rows 1 to 27, 17 parameters each. `ITEM-219`: the readers of parameters 0, 1, 4, 10 and 16 are Unknown. `ITEM-221`: parameter 11 is the range byte, not scaled. `ITEM-222`: the code's row field is 5 bits and LOAD rebinds the archived row. `ITEM-223`: the row reaches the pictures, the hero class, the shop candidates and the SAV | `data/items.toml` `[[weapon]]` takes the lowest free weapon row (28 to 31) as a copy of `base`: every parameter, the masks, each pair's pictures and the body are the base row's, and `price` (2), `weight` (3), `damage-min` and `damage-max` (6, 7), `to-hit` (8), `defence` (9) and `range` (11) may be set; any other key is refused. The hero's class key is the base row's; a weapon-bodies record may choose another drawn body. SAVE writes each item of the row as the same pair of the base row (`F40`, `T0C`) and lists the object with its true code and row in the mod mark; LOAD under the same mod set writes them back; a save whose mark lists no such object holds shipped items only | DEVIATION | The original's weapon table has no row past 27 and its save holds a shipped row; the code stays 16-bit | A decoded reader of parameter 0, 1, 4, 10 or 16, or a wider item identity in the save format | ACCEPTED |
| DIV-4007 | mods / two mods on one item row | Owner direction as `DIV-3909` | `DAT-MATMASK-020`: a row's masks and parameters are installed data; the original reads no mod | `data/items.toml` merges through `mod.Merge` over layer 0, the shipped armour, shield and weapon rows with their masks. A field is one number of a shipped row (`price`, `weight`, `defence`, `absorption`) or one mask bit (`<tier> <material>`); an added item or weapon row is a new key, replaced whole by a later mod. Two mods on one field or one key need `load-after`: the later wins and `againrom -check` names the override; without an order the launch is refused naming both mods. Two changes of one field from two mods once both applied, the later last and unnamed; that pair of mods is now refused without `load-after` | DEVIATION | Owner direction as `DIV-3909` | An owner decision on another rule for two mods | ACCEPTED |
