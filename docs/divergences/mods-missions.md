| DIV-3215 | mods / a mission text written in UTF-8 | Owner: a mod author writes a mission's texts in UTF-8 and the game encodes them for the running install (audit item I7), story 1428 | `MISSION-TEXT-005`: the event page is `text/battle/m<mission>/event<NN>.txt` in the install's own bytes; `TRIG-MSGCORPUS-049`, `TRIG-MSGLIMIT-050`: the shipped pages and what a consumer may change; `TOWN-044`: the world map reads `title.txt` and `briefmap.txt`; `TRIG-TIPS-087`, `TRIG-TIPS-088`: tip pages. No claim says how a mod writes a page | Every `*.txt` file of a mission entry's `texts` folder that is valid UTF-8 is encoded to the install's bytes under the install's language selector, rune by rune, by `textinput.EncodeRune` (the encoder `EncodeInstallText` uses for `title` and `briefing`), and served at `main/text/battle/m<number>/<name>`. A control byte (the CR LF line ends, a tab) is kept as it stands. One mod folder reads right on the English and the Russian base | DEVIATION | Owner direction; one authoring alphabet for every base | An owner decision on a per-file encoding key | ACCEPTED |
| DIV-3216 | mods / a character the install cannot encode | Seat choice under `DIV-3215`: the encoder is `EncodeInstallText`, which drops what it cannot encode | The install's text is one single-byte alphabet; no claim says what a page may hold outside it | A character the install's alphabet has no byte for is dropped from the served page, as `EncodeInstallText` drops it from a title or briefing: on the English base the accented Latin letters are dropped (the installed English pages hold ASCII only), and on the Russian base `Ё` and the 47 code points `DIV-2330` names are dropped. The Byte Order Mark and a no-break space are dropped too. A mod that needs the letter writes the page for that base. Before the drop, a typographic character takes its plain form on both bases (one table, `modTextFallback` in `pkg/game/installtext.go`, used by the text files, `title` and `briefing`): `« » “ ” „ ‟` to `"`, `‘ ’ ‚ ‛ ‹ ›` to `'`, `‐ ‑ ‒ – — ― −` to `-`, `…` to `...`, the no-break space, the narrow no-break space and the thin space to a space. The map check warns, once per file, of a character still without a byte (`mod-message-text`); the Byte Order Mark is dropped without a warning | DEVIATION | A visible placeholder would put a byte in a page that no installed page holds | A claim naming the English font's accented glyphs, or an owner decision on a placeholder | ACCEPTED |
| DIV-3217 | mods / a text file that is not UTF-8 | Seat choice under `DIV-3215`: mods written before this rule keep working | The original reads its pages as installed bytes | A `texts` file that is not valid UTF-8 is served byte for byte, as before. A file of pure ASCII is both and is served unchanged. The installed Russian pages (321 files) and English pages (318 files) are all either ASCII or invalid UTF-8, so a copy of an installed page is never read as UTF-8 by mistake. Boundary: an install-encoded Russian file whose every byte above 0x7f forms a valid UTF-8 sequence is read as UTF-8 (CP866 `e2 a0 ac` is U+282C and the page is served empty); a file of one or two short words can meet it, whole sentences of the installed corpus do not | DEVIATION | A UTF-8 test of the whole file is the only marker a plain text file carries | An owner decision on an explicit encoding key | ACCEPTED |
| DIV-3218 | mods / the world map's mission text | Owner: a mod gives the world map's mission text (audit item I7), story 1428 | `TOWN-044`: the world map reads the mission's `title.txt` and `briefmap.txt` from `text/battle/m<number>/` | A mission entry gives `briefmap.txt` as a file of its `texts` folder, in UTF-8 under `DIV-3215`; the world map shows it for a replacing mission. | DIV-3219 | mods / copying an installed mission's texts out | Owner direction of `DIV-3215`, story 1428 | The original has no copy tool | `cmd/modmission` writes the installed event pages, tip pages, `title.txt`, `briefing.txt` and `briefmap.txt` of the mission into the mod folder as UTF-8, decoded by `textinput.DecodeByte` (the exact inverse of `EncodeRune`). | DIV-3256 | mods / the map of a mod's mission is checked by the map editor's rules | Owner: one rule table judges a map wherever it enters the game from a mod or the editor (architecture audit, decision 1), story 1432 | The original builds a mission from `scenario/<n>.alm` without a check of the map against a rule table (`DIV-3141`) | When the mods load, `SetModMissions` runs the map editor's rule table (`mapRules`, `pkg/game/mapcheck.go`) over the map of every mission a mod declares, guest and replacing, through the one entry the editor's report also uses (`CheckModMap`). A finding of an error rule refuses the mod: the mod, the file, the line, the rule and its message, in the starter's check output and on the launcher's standard error. A finding of a warning rule refuses nothing and is printed as a `warning:` line of the same mod, file and line on standard error, which the starter's check shows. The rule `mod-message-text` reads the texts the mission entry ships. The rules read the tables the front end holds after the mod's item, character and companion tables, so an item a mod adds is known to them; a structure class a mod adds is not (`checkStructureKind` consults the installed `structures.reg`). Census: the 28 numbered scenario maps of the English install and of the Russian install, each as a replacing mission with no texts of its own, give no error finding | DEVIATION | A map the editor reports as an error no longer loads because a mod names it | An owner decision to load a map with an error finding | ACCEPTED |
