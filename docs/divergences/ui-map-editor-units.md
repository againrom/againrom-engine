An npc record the game composes from the starting hero (`REG-SCN-098`; shipped placements EN and RU `70.alm` unit 105 on record 23, `100.alm` unit 112 on record 24) reaches no row of the install's table alone: `mapload.IdentifyAt` reads it over the same composition test play applies (`tableForHero`, once per starting-hero kind) in the mission test play starts the map as, so the choice shows the named character by record, the label and the Who entry say companion by the starting hero, the meaning names the Humans row each hero kind gives it, and the speaker line says the speaker depends on the hero. Choosing the identity the unit has writes nothing. A kind change keeps every flag bit but bit 0, so a unit that becomes a person brings bit 7 (the gear gate) and bit 2 that the person arms read under `ALM-FLAGPATH-109` and the creature and npc arms do not; the popup shows the gear gate as a field for such a person, and no shipped unit carries bit 7 (EN and RU). The class key, secondary key, npc flag and definition id are not fields: a collapsed Map keys line shows each read-only with what it does on the unit's arm or that it is not read, and a set of any of them is refused.
