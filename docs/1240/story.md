## As built

`Entity` has separate active and pending IDs, kinds and presence. Player Attack
and the script's admitted explicit Attack queue a different endpoint behind a
loaded cycle. Repeating that endpoint changes no active inputs. Naming the
active endpoint cancels the queue. A third admitted endpoint replaces it. An
absent endpoint leaves the accepted request; the existing preference veto
replaces primary action with acquire. Move, Defend, Patrol, structure use, Hold
and existing action cancellation clear the request. Terminal target cleanup
clears each endpoint separately, so an old lethal strike retains the next one.
The inherited target-loss policy clears the active phase immediately; it does
not preserve recovery for a nonexistent active victim.

Ordinary saved state-3 dispatch reissues pending 5 without replacing the active
cycle. AI acquisition still uses its previous active-target replacement/reset
path. This is not the native common tail's phase-preserving implementation.

becomes active. A new automatic cast waits for this transfer instead of repeatedly
claiming the old victim. The dispatch placement is authored; no universal native
T0+2 offset is claimed. Weapon-backed loaded casts retain active victim, phase,
countdown, weapon spell and level. Transfer retains equipment, so the next cycle
selects its current weapon mode normally. Manual cast setters are unchanged.

structure, with the ID in the otherwise inactive X operand and zero Y. Tags 0
and 1 retain their old meaning. Pending intent excludes destinations, routes,
stall and structure use. Writers and atomic decode enforce this invariant.

optional healing meaning. World hashing, typed Actions, actor identity remapping

transit. Unsupported records remain ordinary supported saves with bounded debt.
