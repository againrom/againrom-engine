Original mission LOAD is checked against independent Player and Diary bytes.
`TestMilestone2Players` discovers the save corpus and separately compares the
retained complete Document and the represented live state. The registered
`TestReleaseMilestone2Players1154` drives title and mission-menu original LOAD,
ordinary menu SAVE, fresh FrontEnd LOAD and twenty advancing equal World hashes.

## Authority and scope

`SAV-HEAD-025` and the amended `SAV-STREAM-013` define root count and archive
tags. `SAV-PLAYER-028` and `SAV-OBF-029` define the seventeen-field Player run,
including both XOR fields. `SAV-662` defines the 32-byte tail.
`SAV-DIARY-042` defines the two independently counted arrays and D2C;
`SAV-667` supplies the sparse projection's construction defaults.
`SAV-668` and `SAV-669` bound entry meaning and owner identity.

Only decompression, structural starts and original archive indices come from
production. Group counts and actor-reference tags are read from raw bytes
under `SAV-GRPSAVENEXT-572`; missing Group or tag locations fail against those
counts. This supplies direct Player containment independently of decoded
actor/reference lists. Expected values and Diary counts also come from each
source body's bytes. Transient decoder origins supply the
archive-to-Document correspondence; its decoded values are discarded.
Distinct source identities must map injectively. Null and repeated roots,
equal-valued distinct Players, equal-valued distinct tagged Diaries and true
Diary aliases have separate controls.

All seventeen Player fields, Raw10, PRaw32 and each owned Diary's complete
arrays, counts and D2C are compared with the retained Document. Live checks
cover exact Player identities and Slots, unambiguous native purses and the
unique Participant-zero Outcome. `SAV-GRPOWNER-561` makes one direct enclosing
Player an unambiguous source for a live actor's copied F58 mana-reserve value;
other or absent actor bindings are named as exclusions. This is a bounded
Player-derived value check, not a complete Unit audit.

The live Player Diary belongs to PartyWalk's first non-null root. That is a
different selection from Participant-zero and is never inferred from Slot.
The other live Diaries belong to admitted living Humans in that root's group
graph. Every other Player and Humanoid Diary remains a complete-Document
comparison, including non-live subjects. The instrument prints both populations.

62 world-half, 39 between-mission and one named unreadable file. The world
population contains 325 raw Player root slots and distinct archive identities,
10400 tail bytes, 417 owned Diaries, 99246 array elements and 193 nondefault

carrying 189 nondefault entry pairs. Corpus size is reported, never pinned.

## Open boundaries

PRaw32 is retained; formation is not imported. `MOVE-GATE-035` reads the
Group's explicit owner, while `SAV-GRPOWNER-561` permits that owner to differ
from the enclosing Player and the corrected actor owner. Exact purse/Slot
bindings therefore do not settle formation ownership. DIV-957 remains open.
The other tail bytes retain DIV-958's unknown consumers. Diary values have no
newly invented gameplay meaning or consumer; DIV-956 remains open.

Both install roots consume the same owner-written source. This evidence
establishes this engine's LOAD and native persistence, not a new ROM1 runtime
acceptance result. Between-mission files are counted but are outside this
mission instrument's live comparison. The raw reader preserves unequal Diary
array lengths; unsupported live import shapes remain explicit refusals.
