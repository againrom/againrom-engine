# Generated town save conversion

An eligible city created in Againrom can be converted from AGS to SAV through
`saveconvert`, using the same native city writer as ordinary town SAVE. The CLI
previously refused every city without an imported-city baseline before reaching
that writer. This completes the existing generated-city route, not a world
writer or original-runtime interoperability proof.

Restore the AGS through the production front end and snapshot its installed
state. Imported cities keep their original writer and equality checks; native
campaigns use `ExportNativeCitySave`. Preserve the existing representability
refusals, explicit paths, source label or explicit override, output bounds,
no-replace publication and both install fences. World conversion remains refused.

The original framing authority remains SAV-ORIGWRITER-396; SAV-ORIGVALUE-399
separates structural validity from original runtime acceptance. Generated-city
construction and its existing limits remain owned by stories1125..1129 and
their divergence rows. This story adds no new original fields or defaults.

Two registered EN/RU releases cover the route. The game witness uses ordinary
tavern hiring and school input: five members and gold4999280, exact hero stats,
equipment, inventory, learned spells and mercenary pools/flags. A fresh front end
loads the emitted SAV without an original store, trains again, checks the debit
and performs ordinary SAV SAVE. Quick spells, pending return, outstanding offer
and mission state retain their writer refusals.

The command witness uses three fresh entry-point processes: generated AGS to
SAV, SAV to AGS, and source-free AGS to SAV after deleting each prior input.

no-replace output, valid world/quick-spell refusals and unchanged inputs are
asserted. Mission20 return is controlled city setup, not a played mission.
The existing imported-city fresh-process witness still rejects changed Humans
and forged baselines and checks both install fences.
