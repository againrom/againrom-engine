# Saved actor and container load

## Result and scope

Original SAV LOAD must preserve the saved actor's current load, own-weight,
capacity and speed, together with its ordered container, presence, next-insert
index and signed accumulator. The source current load is not reconstructed from
items on LOAD. This applies to the party and uniquely matched living actors
through both App LOAD doors.

The same live state must survive native SAVE/fresh LOAD and mission-to-city
carry. A subsequent transfer updates both actors; equipment, skill and potion
producers must apply established source producer laws while preserving the
complete coherent live basis. Unsupported source mutations must refuse
atomically. City cards and headless inspection must read current state.

## Authority

Pinned ITEM-CONT-004, ITEM-STACK-003, ITEM-LOAD-005 and SAV-CARRY-050 establish
the container and weight operations. SAV-HUMRESUME-460 and SAV-HUMFIRST-465 do
not establish a universal derive-before-first-read boundary. SAV-CITYMOVE-512,
SAV-CITYSALE-513 and SAV-CITYRETURN-514 distinguish carried/table movement,
conditional sale refresh and bulk return. The existing city sale contract
remains in force. Saved zero is data, not an absent-value sentinel.

## Touched surfaces and required proof

The slice touches SAV projections, live simulation holdings/load, native
persistence, party carry, city mutation and display. Independent literal wire
constructors test stale current loads, signed accumulators, absent/empty
containers, duplicate ordered entries and insertion indexes. Required tests
exercise the actual next transfer, equipment or skill/potion action and
native/city continuation. Natural EN/RU source-to-App witnesses must compare
raw saved words, not production-derived expected values. Genuine old-native
and city policy controls must retain their compatibility semantics.

## As built at the equipment checkpoint

The live bookkeeping/import/ordered-container and form-75/city-policy-5 wiring
is implemented. Literal App tests pass through both LOAD menus: stored loads
53 and 0 survive first read, an equal-quotient transfer updates both signed
accumulators, and ordinary SAVE/fresh LOAD preserves them. City literals retain
current load90 through tray staging/bulk return while individual return refreshes
it to57; the player card reads those values. The sim, mapload and game package
tests pass, including their existing frozen older-save controls.

The full retained Human/Humanoid basis now reaches the live load callback,
skill sink, selected permanent/timed potion producers, city potion and carry.
Unit's load callback updates only mana floor. A pure stateless arithmetic rule
is rebound before a native world executes source producers. Literal tests
cover the full load-derived sheet and both App LOAD doors through SAVE/fresh
LOAD and the next transfer. They are synthetic controls, not original-runtime
observations.

Exact Weapon/Armor/Shield runtime operands now cross Piece, ItemInstance,
ordered stacks, native and city boundaries. Saved definition row and own-kind
are separate; original LOAD binds only the reached Weapon columns from that
row. DIV-762 retains distinct operands in distinct stacks. The optional source
item prefix leaves source-free form75 worlds unchanged.

Actual Weapon/Armor/Shield attach, removal, replacement, worn drop and terminal
loot use the promoted class-specific ordering in SAV-EQUIPORDER-552,
SAV-EQUIPEFFECT-553 and SAV-EQUIPCALL-554. Every admitted state-0 Effect reaches
its own derive before the next Effect. Ranged to-hit removal is not an inverse;
melee active skill comes from definition parameter5, while post-derive range
uses current W50. Both mission commands and city pack/shelf/table/doll actions
stage the whole change, including purse and displaced items, before commit.
DIV-445's accepted stricter shield policy remains in force.

Source potion, scroll refund, transfers, sacks, terminal loot and city changes
refuse without committing a callback prefix. Generic timed effects retain
nominal source operands and use the retained dispatcher at application and
expiry. They do not fall back to native arithmetic. School training after an
equipment change keeps the source Human basis and source price.

Native-generated equipment in a source world receives integer constructor
operands from the resolved definition tables. These are hashed alongside the
world's existing code/weight declarations and survive a fresh native decode.
Explicit saved instances are never refilled from appearance Code. This binds
only reached producer fields; zeroed unused bytes in a new canonical value
are not a claim about original uninitialized constructor tails.

SourceActor is 209 bytes and the actor-load record is 224 bytes. The sparse
source-equipment value is 77 bytes, including reached Weapon columns,
Weapon-owned Spell values and an unsupported-effect-state marker. Current
gob descriptors changed; frozen published envelope bytes were not rewritten.

Literal action tests cover melee/ranged/armor/shield, partial stacks,
same-slot return, opposite-hand displacement, ordered effects, late refusal,
Weapon-owned Spell preparation/removal, generated items and native next
removal. City tests cover four item origins and fifteen atomic refusal cases.
Natural staff inputs are independently anchored to SAV offsets and checked
through App LOAD, native SAVE/fresh LOAD and controlled loot/re-equip.
These are implementation continuations, not original-runtime observations.
Exact checkpoint commands and remaining gates are in `handoff.md`.
