# Hotfix ledger

A **hotfix** is a small correction to a defect the owner can see, committed straight to `master`
without a story: no `docs/<NNNN>/` folder, no lane, no SDD artifacts, no task trailer. Owner's
call, 2026-08-07, on the finding that twelve stories had landed while the game's only playable
mission stayed broken. *Лучшее враг хорошего.*

This file is the **only** record that they happened. It exists so the clauses they imply can be
folded into the specs later, and so that a reader of `docs/<NNNN>/` never has to wonder why the
code says something no spec does.

**One row per hotfix. The row's first column carries the fix's own commit hash, so the row lands in
the commit immediately after the fix** — a row written inside the fix's own commit would have to name
a hash that does not exist yet. This header asked for the same commit from 2026-08-07 until
2026-08-19, and none of the rows below was written that way, because none could be. Neither commit is
pushed without the other. Keep each row to one line of prose:
what the hotfix did in one sentence, its boundary in a phrase, an archive link to the detail moved
to `docs/hotfix/ARCHIVE.md`, and the debt's disposition. The *Owes* column names the story whose
`spec.md` should eventually absorb the rule — that is the whole point of the ledger, so it is never
left blank.

**When a hotfix is folded in, do not delete its row** — mark it, and name the story that took it.
A deleted row makes the code's history unreadable again, which is the thing this file prevents.

## Bounds

Not a story, so not `docs/NNNN-*`. `check-doc-budget.sh` and `check-sdd-audit.sh` globbed that
pattern and would have demanded the six artifacts a hotfix exists to skip; both were retired on
2026-08-15, and the naming rule stands without them. A `docs/NNNN-*` folder is where a reader looks
for a spec, and a hotfix has none.

A change belongs in a **story**, not here, if any of these holds: it needs a research fact that is
not already published; it changes a shipped file's bytes or the byte-form version; it touches the
hashed simulation state's contract; or the fix is large enough that a reviewer would want a spec
to read it against. When unsure, it is a story.

## The check

`scripts/check-hotfix-ledger.sh` was retired on 2026-08-15 with the other checkers, and this section
named it as live until 2026-08-19. It measured each row's length, that no `Owes` cell is blank, the
whole file's size, and that no hotfix was committed without a row. The last of those is the reason
the file exists, it needs no script, and it is this command:

```sh
git log --no-merges --format='%h %s' --invert-grep --grep='SDD-Task:' -- pkg cmd internal \
  | grep -vE '^[0-9a-f]+ ([Ss]tory )?([a-z]+\()?[0-9]{4}[):, ]'
```

It lists every code commit that carries no task trailer and whose subject names no story. Each one
newer than `9729459` must have a row below, and its hash must be in the row's **first** column, which
is where a reader pairing the two lists looks; a hash mentioned only in a row's prose does not
pair. It also
returns **eight commits older than `9729459`** — comment, `chore` and `refactor` commits from before
the trailer discipline tightened. Those are not hotfixes and are named here once so nobody
investigates them twice: `712a106`, `73b6063`, `0c23241`, `cbf7815`, `78a2699`, `9d0eace`,
`cd1ed31`, `1f13af4`. The retired script carried the same eight, for the same reason.

Until 2026-08-10 no script measured this file and the command above was the whole check, run by
whoever remembered. In that time five rows reached 3–6 KB under a header asking for one line, and
eighteen `Owes` debts went undischarged. `0130` paid them and added the script; the detail those
rows carried is in `ARCHIVE.md`. The command is the whole check again since 2026-08-15, so the
length and the `Owes` cell are the writer's own responsibility.
